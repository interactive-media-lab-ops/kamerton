# Збірка тижня · шпаргалка оператора

Одна сторінка. Тримайте відкритою під час першої збірки, далі не знадобиться.

**Скільки це триває:** 60–90 хвилин. Якщо виходить довше, зупиніться і скажіть,
де застрягли: це дефект інструмента, а не ваша вина.

---

## Що потрібно перед стартом

| що | звідки |
|---|---|
| `import.html` | `app/dist-import/import.html`, відкривається подвійним кліком |
| CSV з метриками | saved query BigQuery, зона відповідальності Тимура |
| `import-log.json` | від попереднього тижня; якщо це перший тиждень, файлу ще немає |
| зведення САН за тиждень | для тем, цитат і вердикту |

Мережа не потрібна. Сторінка працює офлайн.

---

## Порядок дій

**1. Стартова точка.** Три входи, вибираєте один:

* **«ПОЧАТИ З W{n}»** це основний шлях. Береться минулий тиждень і зсуваються дати.
* **«ЗАВАНТАЖИТИ EXCEL»** якщо тиждень уже зібрано в таблиці. Порожній бланк
  дає кнопка «ПОРОЖНІЙ ШАБЛОН»: сім вкладок з правильними заголовками.
* **«ЗАВАНТАЖИТИ ЧЕРНЕТКУ JSON»** якщо чернетку підготував AI-асистент.

При клоні вердикт, цитати і методологічні правила НЕ переносяться навмисно:
скопійований вердикт це найшвидший спосіб видати минулий тиждень за новий.

**2. Шапка і висновок.** Перевірте період. Впишіть загрозу і можливість тижня:
по одному рядку, це те, що керівництво прочитає першим.

**3. Метрики.** Кнопка «ІМПОРТ МЕТРИК З CSV». Числа руками не переносьте
взагалі: це головне джерело помилок, які потім неможливо знайти.

**4. Теми.** Правиться дельта, а не весь список. Тон це число від −1 до 1.
Рядок підсвітився жовтим: ви взяли id, який злитий з іншим. Візьміть канонічний,
інакше історія теми обірветься.

**5. Діф і превʼю.** Подивіться, що нове, що зникло, що зсунулось. Під діфом
малюється карта тем: позиції рахує той самий модуль, що і випуск, тому це
справжнє розташування, а не приблизне. Якщо зникло щось, чого ви не прибирали,
поверніться до кроку 4.

**6. Ворота чесності.** Тут інструмент вас не пустить далі, і це задум.
Кожен прогноз, чий дедлайн настав, вимагає вердикту: **влучив / промах / скасовано**.
Скасування вимагає причини. Реєстр не має права забути прогноз, зокрема промах.

**7. Валідація.** Червоне виправляється, жовте читається і зважується.
Повідомлення кажуть поле і що саме не так.

**8. Затвердження.** Впишіть своє прізвище, підвантажте `import-log.json` від
минулого тижня. Кнопка «ЗАТВЕРДИТИ І ВИВАНТАЖИТИ» віддасть три файли:
`weeks.json`, `import-log.json` і архів входу `kamerton_W{n}_vhid.zip`.

---

## Куди покласти вивантажене

```
weeks.json                ->  app/src/data/raw/weeks.json   (замінити)
import-log.json           ->  docs/import-log.json          (замінити)
kamerton_W{n}_vhid.zip     ->  архів входу, покладіть у сховище тижнів
```

Далі одна команда з теки `app`:

```bash
npm run check && npm run build
```

Готовий випуск: `app/dist/kamerton.html`. Один файл, відкривається з диска,
мережі не потребує.

---

## Якщо щось пішло не так

**Кнопка затвердження сіра.** Під нею написано, чого бракує: помилки валідації,
непройдені ворота або не вписане прізвище.

**`npm run check` впав.** Тиждень не поїде, доки не зелений. Прочитайте повідомлення:
воно українською і каже поле. Якщо не зрозуміло, надішліть текст помилки розробнику.

**Помилилися після затвердження.** Нічого страшного: журнал тільки дописується,
попередні записи не зникають. Зберіть тиждень заново і вивантажте ще раз, у журналі
буде видно обидві спроби.

**Не чіпайте руками:** `app/src/data/derived/` і `app/dist/`. Це похідні файли,
вони перебудовуються самі і будь-яка ручна правка в них загубиться.
