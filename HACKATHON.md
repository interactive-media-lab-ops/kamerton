# КАМЕРТОН · пакет для хакатону

Стан репозиторію на 06.11.2026: усі текстові перевірки зелені
(`npm run verify`), продукт збирається в один файл 831 КБ, корпус 7 тижнів
(W29..W35, W29 прихований). Цей файл каже, що це за продукт, як його побачити
за 5 хвилин і які задачі можна брати.

## Що це

Офлайн-односторінковий застосунок для керівництва без аналітичної підготовки:
щотижневий зріз інформаційного поля. Один файл `kamerton.html` відкривається з
диска без мережі. Критерій прийнятності один: **перший висновок читається за
30 секунд**.

Три шари на одному екрані (перемикач у шапці):

* **ТЕМИ**: карта-галактика. Кожна зоря це тема тижня, радіус це вага, колір
  це тон, обводка ядра каже, чим є твердження (суцільна факт, штрих оцінка,
  крапки гіпотеза). Супутники навколо зір це відкриті кейси.
* **АКТОРИ**: ті самі теми очима інституцій, аудиторій і груп; звʼязки лише
  там, де їх назвав аналітик.
* **КОМПАС**: ринки прогнозів, ставки учасників, рахунок влучань і промахів.
  Одне число живе в одному місці: ринок посилається на `Forecast` за id.

Плюс вкладка **СЮЖЕТИ** (глибинний шар: три лінзи на реакцію аудиторій),
режим **ІСТОРИЧНІ ПРЕЦЕДЕНТИ** (клік по супутнику кейса) і **PLAY**: показ
корпусу день за днем, де проміжні дні чесно підписані як інтерполяція.

## Побачити за 5 хвилин

```bash
cd app && npm ci && npm run build
open dist/kamerton.html            # або подвійний клік у Finder/Провіднику
```

Корисні адреси: `kamerton.html?week=2026-W32` відкриває конкретний тиждень.
Клавіша `?` показує коуч-мітки. `Esc` закриває будь-яку шухляду чи режим.

Імпортер тижня (інструмент редактора, не продукт): `npm run build:import`,
далі `dist-import/import.html`. Як ним зібрати тиждень: `docs/import_cheatsheet.md`.

## Архітектура на один екран

```
raw/weeks.json ───────────────────────── сирці, недоторканні
   │   corpus/precedents/*.json ──────── історичні кейси
   │   corpus/depth/*.json ───────────── розмітка глибинного шару
   │   registry/*.json ───────────────── стабільні id тем, акторів, кейсів
   ▼
scripts/build-*.mjs ──────────────────── проєкції (prebuild)
   ▼
derived/*.json ───────────────────────── те, що їде в бандл
   ▼
src/data/selectors.js ────────────────── ЄДИНІ двері до даних
   ▼
src/map/  src/panels/  src/plots/  src/play/  src/graviton/ ── екран
```

Правила, які не обговорюються, в `CONTRIBUTING.md` (10 пунктів) і
`docs/DEVELOPMENT.md`. Головне: продукт не має домальовувати дані і не може
робити хибний сигнал «зручнішим». Якщо виміру немає, це має бути видно.

## Що змінено на підготовці (06.11.2026)

* `npm run check` знову зелений: тест плавності індексу PLAY рахує поріг з
  тижневої дельти, а не з жорсткої одиниці (W34 -> W35 дав 26 -> 49).
* Контракт іде в бандл проєкцією `derived/contract.json`
  (`scripts/build-contract.mjs`): без полів, яких екран не читає, і без
  карток прецедентів, що клонувались з тижня в тиждень. Мінус 59 КБ.
  `check:contract` звіряє відбиток сирців у проєкції.
* Ліміт бандла піднято з 750 до 900 КБ. Розклад виміряний по модулях: дані
  ≈ 450 КБ, react-dom 130 КБ, код застосунку ≈ 190 КБ, CSS 80 КБ. Рішення
  потребує підтвердження власника продукту (Р. Савицький).
* Два довгі тире прибрано з UI (`PrecedentsMode.jsx`); інваріант тепер
  відрізняє UI від цитат у контракті.
* Структура: історичні документи в `docs/archive/`, пілот F0 у
  `docs/pilots/`, `public/compare.html` більше не їде в `dist/`. Додано
  `CONTRIBUTING.md`, `.editorconfig`, `.nvmrc`, `npm run verify`,
  GitHub Actions (`.github/workflows/check.yml`).

## Відкриті задачі

Нумерація умовна. У кожної є критерій прийняття; без нього задача не
вважається зробленою. Складність: S до 2 годин, M пів дня, L день і більше.

### Код

**1. [S] `qa:ui`: тест «після виходу з PLAY нуль руху» застарів.**
Супутники кейсів обертаються в спокої за свідомим рішенням
(`src/map/galaxy.js`, блок «ДВА ГОДИННИКИ ПОЛЯ»), а тест у
`scripts/ui-smoke.mjs` порівнює два знімки полотна і бачить рух.
Критерій: тест міряє амбієнт (туманність, пил, ореоли), а не супутники,
наприклад знімає на тижні без кейсів або маскує орбіти; `npm run qa:ui`
зелений без послаблення правила про нуль idle-анімацій.

**2. [S] `qa:f3`: три текстові очікування від попереднього дизайну режиму
прецедентів.** Документовано в `docs/DEVELOPMENT.md`. Критерій: smoke-тест
оновлений під чинний UI (`PrecedentsMode.jsx`), три перевірки зелені, жодна
не видалена без заміни.

**3. [M] `qa:plots`: тултіп довгої назви іноді виїжджає за лівий край.**
Вузол «Звинувачення командування 225 і 425…» на вкладці СЮЖЕТИ: тултіп
притискається до кадру (`PlotsScene.jsx`, `useLayoutEffect`), але шар їде з
паралаксом, і замір ловить рамку з x = -47. Сам QA-скрипт уже двічі
переписував очікування під час. Критерій: притискання враховує паралакс
(або паралакс не рухає тултіп), перевірка стабільна на десяти прогонах
поспіль.

**4. [M] Структурні тести імпортера.** `importer/` має ворота чесності
(прогноз із дедлайном у тижні не пройде без вердикту), але їх покриває лише
`check:new`. Критерій: окремий `check:importer` на `importer/lib.js`
(клонування тижня, ворота, журнал імпорту append-only), без браузера.

**5. [L] Стиснути дані в бандлі.** Дані ≈ 450 КБ з 831. gzip + вбудований
інфлейтор (без мережі, без нових залежностей у продакшн-бандлі, або з
вендореним інфлейтором за рішенням власника) дав би ≈ 500 КБ. Ускладнення:
`selectors.js` синхронний на рівні модуля (`WEEKS`, `META` це константи),
тому або синхронне розпакування при завантаженні модуля, або асинхронний
старт у `main.jsx`. Критерій: `check:invariants` зелений із лімітом 750,
`npm run check` без змін, час до першого кадру не гірший.

**6. [M] Лінтер.** У репозиторії його немає; `eslint-disable` у скриптах
стоять «на майбутнє». Критерій: конфіг без нових правил стилю (мета ловити
помилки, не переформатовувати), `npm run lint` у `verify` і в CI, нуль
правок у поведінці коду.

### Дані й редакція (потрібен редактор тижня або власник)

**7. Девʼять прострочених прогнозів без вердикту.** `check:new` показує:
«ворота бачать прострочені прогнози (9)». Реєстр append-only, прибрати їх
не можна. Критерій: кожен отримує `hit` / `miss` / `void` з причиною через
імпортер, `migration_v2.md` доповнений.

**8. Картки прецедентів для W34 і W35.** Кейсів 4, карток 0
(«чесний порожній стан»). Корпус має 11 історичних кейсів
(`corpus/precedents/`). Критерій: картки за шаблоном
`docs/pilots/F0_pilot_template.md`, з «де аналогія ламається» і «що
спостерігаємо», проходять `check:corpus`.

**9. Одинадцять довгих тире в `raw/weeks.json`.** Цитати респондентів
лишаються дослівно; нотатки аналітика (`note`, `opportunity`,
`bluf_opportunity`, `resolution_note`, `method_notes`; усі сім у W33) можна привести до правила 4.7
міграцією. Критерій: міграційний скрипт зі звітом, цитати (`quotes[].text`)
не торкнуті, `check:invariants` показує 4 тире замість 11.

**10. Довідник лінз v1 не має позиції для конструктивного наративу.**
Три теми (вдячність, памʼять, волонтерство) зрізані з однією причиною: «у
довіднику немає позиції». Це питання до зустрічі в `corpus/depth/`, не
задача для коду. Критерій: рішення власника, оновлений
`registry/lenses.json`, перевалідована розмітка.

### Продукт (ідеї, без критерію, обговорити з власником до старту)

* Експорт тижня в друк: одна сторінка A4 з BLUF, балансом і трьома
  найяскравішими темами. Продукт офлайн, тож тільки `window.print()` і CSS.
* Режим «що змінилось від минулого тижня» як окрема оверлей-легенда поверх
  карти (дельти вже рахуються в `selectors.js`).
* Доступність карти з клавіатури вже є (`MapKeyboardIndex.jsx`); перевірити
  читачем екрана, чи озвучуються статус і тон зорі.

## Чого не робити на хакатоні

* Не додавати залежностей у продукт (React 18 і все). Dev-залежності за
  рішенням власника.
* Не чіпати `raw/weeks.json` поза міграцією.
* Не вигадувати тексти UI і не вигадувати історичні кейси: кожен факт у
  корпусі має два і більше джерел (`check:corpus`).
* Не «підганяти» тести під результат: якщо тест не зійшовся, спочатку
  зʼясуйте, що саме в даних змінилось (приклад: коміт про поріг індексу PLAY).
