# КАМЕРТОН · застосунок

Щотижневик з памʼяттю для військового керівництва. Читає контракт тижня, сам рахує
дельти і рендерить карту з панелями. Дизайн-система: Астролябія (`../astrolabe-ds`),
підключена локально, її код не копіюється і не переписується.

## Команди

```
npm ci           # залежності за package-lock.json
npm run dev      # дев-сервер
npm run build    # dist/kamerton.html, один файл, працює офлайн
npm run check    # перевірки шару даних і розкладки карти
npm run verify   # check + build + інваріанти продукту + недоторканість сирців
```

Продукт це `dist/kamerton.html`. Файл `index.html` у корені застосунку це точка входу
для дев-сервера, подвійним кліком він не працює.

Тиждень можна відкрити напряму: `kamerton.html?week=2026-W30`.

## Як додати новий тиждень

Весь тиждень це один обʼєкт у `src/data/raw/weeks.json`, у масиві `weeks`, доданий у кінець.
Коду міняти не треба: дельти, серії, ранги, вік кейсів, рахунок реєстру і розкладка
карти перераховуються самі. Звичайний шлях для редактора це імпортер
(`docs/import_cheatsheet.md`), ручна правка сирців нижче — для розробника.

1. Скопіюйте обʼєкт останнього тижня як зразок і замініть `id` та `period`.
2. Заповніть поля. Обовʼязкове мінімально:
   - `verdict.threat`, `verdict.opportunity`, `verdict.editor_status`
   - `indices`, `balance`, `states` з числами тижня
   - `topics`: кожна тема з `id`, `name`, `aud`, `trend`, `tone`, `verification`
     і **`salience` 1..5** (радіус зорі рахується як `14 + salience * 5`)
   - `topics_exited`: теми, що випали з поля, з `reason`
   - `cases`: кожен кейс з `id`, `title`, `opened`, `status`, `next_check`
     і **`host_topic`** (тема, навколо якої кейс обертається супутником)
   - `forecasts`, `uncertainties`, `method_notes` за потреби
   - **`actors`**: масив `{id, stance (-1..1), activity (1..5), note, links}`,
     де `links` це `[{to, tone: "r" | "g"}]`
   - **`levers`** з `key`, `expected`, `confidence`, а для режиму моделювання ще
     `cascade` (`[{actor, stance, note}]`) і `rope_after`
   - **`sandbox`**: `{topic, topic_label, horizon_days, rope}` для каната прогнозу
3. `links` у темах ставте тільки там, де звʼязок названий у звіті. Немає links,
   немає лінії на карті: карта не має стверджувати того, чого не стверджує аналітик.
4. Кожен `id` актора має існувати в `actors_registry`. Новий актор спершу додається
   в реєстр, потім використовується у тижні.
5. Перебілдіть: `npm run build`. Він сам перераховує похідне (`prebuild`): ансамбль,
   проєкцію контракту `derived/contract.json`, прецеденти, глибинний шар, гравітон.
   Без перебудови правка сирців до екрана не дійде, і `npm run check` це скаже.

### Чого робити не треба

- Поля `delta` заповнювати не обовʼязково. Дельти рахуються з сусідніх тижнів,
  а `delta` з контракту використовується тільки як запасний варіант, коли
  попереднього виміру немає. Видалення `delta` нічого не ламає.
- Ранги тем проставляти вручну. Є `weight_pct`, ранжування йде за вагою; немає,
  ранжування йде за трендом.
- Статус `festering` у кейсах ставити руками. Кейс, відкритий три тижні й довше
  без відповіді, показується як загноєний сам, а в даних лишається `open`.

### Перевірка після додавання

```
npm run check
```

Набір звіряє дельти, серії, вік кейсів, рахунок реєстру і геометрію карти:
що жодна зоря не ховається під панеллю, що підписи не налазять, що теми за межею
поля справді лежать за межею.
