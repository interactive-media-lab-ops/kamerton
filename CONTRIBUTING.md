# Як працювати з кодом КАМЕРТОНА

Коротка інструкція для того, хто бере задачу. Повні правила в
`docs/DEVELOPMENT.md` (обовʼязково) і `docs/CODE_SPEC.md` (архітектура, чому
саме так). Цей файл не замінює їх, а каже, з чого почати і що здати.

## Старт за 10 хвилин

```bash
cd app
npm ci                  # Node 20+ (див. .nvmrc)
npm run check           # ~1 хв, усі перевірки шару даних, карти й ансамблю
npm run build           # app/dist/kamerton.html, відкрийте його подвійним кліком
npm run dev             # дев-сервер з гарячим перезавантаженням
```

Для живого браузерного QA один раз: `npx playwright install chromium`.
Потім `npm run qa:shots`, `npm run qa:plots`, `npm run qa:depth` за потреби.

## Перед тим як здати

```bash
cd app && npm run verify
```

`verify` це `check` + `build` + `check:invariants` + `check:raw-immutable`.
Усе має бути зеленим. Якщо ви міняли UI, прикладіть знімки з
`SPEC_NOTES/shots/` (їх робить `npm run qa:shots`) до опису змін: двічі
саме скріншот знаходив те, чого не бачили зелені перевірки.

## Що не можна

Десять правил, за порушення яких зміни не приймаються. Повний список і
причини в `docs/DEVELOPMENT.md`.

1. Компоненти не читають JSON. Вхід до даних тільки через `app/src/data/selectors.js`.
2. Ніхто не пише в `app/src/data/raw/`. Збірка тим більше. Зміна сирців це міграція
   зі звітом у `docs/migration_v2.md`, і запускається руками.
3. Одне число має одне джерело. Не дублюйте числа, статуси, правила.
4. Продукт офлайн: жодних CDN, мережевих шрифтів, зовнішніх посилань, fetch.
5. Нові залежності тільки після рішення власника.
6. Довгих тире в UI немає. Тексти інтерфейсу беруться зі спеки, не вигадуються.
7. Карта не має idle-анімацій (виняток: супутники кейсів, див. `galaxy.js`).
   `prefers-reduced-motion` дає той самий фінальний стан.
8. Епістемічний статус (факт / оцінка / гіпотеза) показується завжди, де є твердження.
9. Не малюйте реальних людей; аудиторії й інституції це гліфи.
10. Не рефакторьте «для чистоти» без конкретного дефекту або задачі.

## Куди дивитись

| Хочу змінити | Починати з |
| --- | --- |
| дані, контракт, похідні | `app/src/data/schema.js`, `selectors.js`, `app/scripts/build-*.mjs` |
| карту тем, анімації | `app/src/map/galaxy.js`, `starfield.js` |
| акторів і підписи | `app/src/map/actorfield.js` |
| панелі | `app/src/panels/` |
| вкладку СЮЖЕТИ | `app/src/plots/`, `app/src/data/depth-block.js` |
| прецеденти | `app/src/panels/PrecedentsMode.jsx`, `app/src/data/corpus/precedents/` |
| КОМПАС (ринки, прогнози) | `app/src/data/ensemble.js`, `app/src/panels/EnsembleBoard.jsx` |
| візуальні токени | `astrolabe-ds/tokens/`, `astrolabe-ds/src/astrolabe.css` |
| пороги й тайминги | `app/src/data/config/thresholds.json` (не в JSX і не в CSS) |

## Коміти

Один коміт = одна задача. У повідомленні: що змінено і чому; якщо правили
тест або інваріант, скажіть, який саме випадок у даних змусив це зробити.
Мова повідомлень українська, як і весь репозиторій.

## Перевірки, які зараз не зелені

Два живі QA-скрипти мають застарілі очікування і відомі дефекти, це не привід
їх «підганяти»: див. `HACKATHON.md`, розділ «Відкриті задачі».
