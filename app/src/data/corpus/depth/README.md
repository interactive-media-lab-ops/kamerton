# Розмітка Глибинного шару

Спека: `docs/KAMERTON_SPEC_deep_layer.md`, версія 0.3.

Тут лежать **три ілюстрації для узгодження довідника**, і жодного матеріалу
звіту. Статус це і є призначення розмітки (розділ 9):

* `draft_for_alignment` — приклад до розмови з Миколою. Стоїть на ще не
  узгодженому довіднику, тому схема забороняє підняти його до `validated`
  і вимагає `alignment_note`: питання, заради якого приклад існує.
* `draft` — робоча розмітка на узгодженому довіднику, до ревʼю.
* `validated` — пройшла ревʼю, має імʼя й дату. Тільки вона йде у звіт.

Один файл = одна `CaseDepthMarkup`, імʼя файлу збігається з `id`.
Рекомендований вигляд id: `dl_w32_case_lviv_tck`.

## Лінзи читаються з поля

Головне правило (розділ 3, не-ціль 5): усі три лінзи зчитуються з реакції
аудиторії, а не з тексту події чи документа. Якщо поле не відповіло, лінза
**зрізається**, а не заповнюється: `cut: true` плюс `reason`.

Зрізати можна будь-яку лінзу, включно з сюжетом. Кейс із трьома зрізаними
лінзами у звіт не йде, але лишається в реєстрі як зафіксоване спостереження
«поле промовчало»: мовчання поля це теж результат вимірювання.

## Що не пропустить `npm run check:depth`

* сюжет, роль або психотип не з довідника `registry/lenses.json`;
* кейс не з реєстру `registry/cases.json`;
* порожня лінза без `cut` або зрізана лінза без причини;
* лінза, яка одночасно зрізана і заповнена;
* `secondary`-сюжет без `primary` або однаковий з ним;
* рівно один психотип (це не розшарування реакції) або четвертий;
* частка психотипу без `method` або сума часток понад 100%;
* три ролі в рядку (розділ 8: максимум дві, решта в примітки);
* блок довший за 8 рендерених рядків або рядок довший за 120 знаків;
* незрізаний сюжет без комунікаційної рекомендації (P0);
* `validated` без імені й дати; `draft_for_alignment` без `alignment_note`
  або піднятий до `validated`;
* позиція довідника, у якої менше трьох тригерів (розділ 10).

Попередження (не блокують): статус розмітки, «поле промовчало», частка не в
усіх кластерів, і збіг зі стоп-листом міфічних імен (не-ціль 1). Стоп-лист не
може бути повним, тому останнє слово за людиною.

## Примітки

`note` це робочий коментар аналітика: у блок звіту він не йде (розділ 8), а в
ілюстрації для узгодження друкується, бо на зустрічі обговорюється саме
міркування. Зрізана лінза теж має `note`: `reason` це рядок звіту і рахується
в ліміт 120 знаків, довге міркування живе в `note`.

Стоп-лист імен усе одно сканує примітки разом із блоком: міфічне імʼя з
робочого коментаря приходить на зустріч і звідти в текст.
